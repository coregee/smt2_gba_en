# Working on the SMT2 GBA decompilation

The goal is source that rebuilds the original ROM exactly, readable enough to explain the
game and to debug the English translation. `python build.py` must print `OK` after every
change; a change that breaks the sha1 is not finished.

## Rules

- Never commit `baserom.gba`, `build/`, `ghidra/` or extracted asset files (PNG, WAV, BIN,
  PAL). The manifests (`assets/manifest.json`, `assets/*/includes.json`) and the text/sound
  sources are committed; the binary files are regenerated with the `extract` commands.
- `asm/`, `data/` and `layout.json` are generated by `tools/disasm.py`. Do not hand-edit them
  except when moving a function to C (below); prefer fixing the generator.
- Names go in `reference/symbols.tsv` with a confidence (`proven`, `probable`, `tentative`)
  and the evidence. English names, `Subsystem_Verb` style for game code; library names as the
  library spells them (`m4aSoundInit`, `__divsi3`, `LZ77UnCompWram`). Never invent a name
  for a function you have not read; `sub_XXXXXXXX` is fine.
- Run `python tools/function_map.py` after naming work.

## Discovery

`tools/trace.py` is authoritative for what is code and in which instruction set. If something
is wrong (a function missing, data decoded as code), fix the tracer or add a seed with a
comment saying how it was found, then `python build.py --regen`. `tools/coverage.py` lists
unexplained gaps in the program segment (currently only module data blocks).

## Assets

`tools/assets/assets.py` (compressed graphics/data), `tools/assets/m4a.py` (music),
`tools/assets/text.py` (text and event scripts). Each has `extract` and a check that the
rebuilt bytes equal the original. When you identify what a blob is (palette, tilemap, sprite
sheet), edit its manifest entry (`format`, `width`, `palette`, a better `name`) and re-extract.
LZ77 and Huffman (with the stored tree) re-encode exactly; record new findings about formats
in `docs/`.

## Moving a function to C

The compiler is pret's `agbcc` (GCC 2.9, `-mthumb-interwork -O2`; the m4a library used
`old_agbcc`), run in WSL; see `docs/matching.md`. Write the function in `src/<module>.c` with a `// Name @ 0xADDR` line
directly above it (a file's functions must be consecutive in the ROM), check it with
`python tools/match.py src/<module>.c --diff`, then `python tools/disasm.py && python build.py`:
the generator drops those functions from `asm/` and places the C in `layout.json` by itself.
While other files in `src/` are still being written, leave them out with
`tools/disasm.py --exclude 'prefix_*'` so the build only uses finished C.
Never run `build.py` in a checkout where `match.py` is in use: a failed link replaces
`build/smt2.elf`, which `match.py` reads for every external address. Integrate in a separate
`git worktree` instead.
The sha1 check is the proof of equivalence. Use `reference/ghidra-c/` as the starting point,
never as the answer. Functions that resist matching stay readable under `#ifdef NONMATCHING`
with the original instructions as a NAKED body (`tools/naked.py`). Names proposed while
working go in `src/<module>_names.tsv`; `python tools/apply_names.py` merges them into
`symbols.tsv` and renames identifiers in `src/` and `include/`.

## Evidence

Say what is proven (instructions, data, the build) and what is inferred. The translation
project's comments are leads from an earlier, lost Ghidra session; names harvested from them
are `tentative` until checked.
